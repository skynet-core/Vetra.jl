# T029 — Optional Unicode shaping and bidirectional text

Status: see [TASKS.md](../TASKS.md). Dependencies: T028 (and its T027 contract).
Goal: correctly position and order glyphs for the documented complex scripts.

## Inputs and scope

Implement T027's selected optional shaper/bidi integration into the additive
layout API. Native Julia still rasterizes glyph outlines. No automatic change
to legacy text behavior, mandatory font engine, or promise of every font format.

## Acceptance criteria

- Shaped glyph IDs, cluster mapping, advances, offsets, and direction match a
  pinned independent shaping reference on licensed fonts.
- Cover Arabic contextual joining, an Indic conjunct, ligatures, combining
  marks, mixed RTL/LTR numbers/punctuation, and fallback/run boundaries.
- Wrapping and shaping interact according to the contract (including reshaping
  at line breaks where needed), with consistent measurement and rendering.
- Missing optional packages give a clear explicit shaping error; existing
  unshaped/native text and core-only loading keep working.
- Document script/font limitations and demonstrate the new path in a multilingual
  card. Do not broaden CFF/TTC/color-emoji claims without separate evidence.

## Validation

Use [shared validation](../docs/ROADMAP.md#shared-validation), T027 reference
outputs, optional-dependency loading tests, and the multilingual example.
Test both glyph/cluster data and rendered placement; visual similarity alone
does not establish shaping correctness.

### Provider and version

- **Option (b) of D031 §6 — selected by the user, recorded as D033**:
  `HarfBuzz_jll` **100.15001.0+0** (JLL wrapper registry; MIT; bundles
  harfbuzz **15.1.0**; 18 platform artifacts; artifact-only deps). It is
  an opt-in `[extras]`/`[targets] test` package (D014/D032 pattern),
  loaded lazily by `Base.require` on the first shaped call with the
  explicit install hint; core-only and legacy-LTR installs never load it.
- Thin `ccall` surface (15 symbols: blob/face/font/buffer/`hb_shape`/
  infos/positions + destroy). Verified ABI facts (probe, recorded in
  D033): `hb_glyph_info_t` = 5×uint32 (gid@0, mask@4, cluster@8);
  `hb_glyph_position_t` = 5×int32 (x_advance@0, y_advance@4, x_offset@8,
  y_offset@12); `hb_direction_t` LTR=4/RTL=5; `hb_script_t` = 4-byte
  tag; `hb_face_create` takes an `hb_blob_t*` (the legacy raw-bytes
  signature segfaults); `hb_face_get_glyph_count` (not
  `hb_face_count_glyphs`).
- Frozen-build `ccall` constraint: the library expression must be a
  constant, so symbols are resolved once through bare `ccall(:dlopen)` /
  `ccall(:dlsym)` (libc; no `Libdl` dependency) into function pointers
  held in the module-global `_HB_FUNCS`; buffers are read with
  `unsafe_load` (1-based index of field k of glyph i, stride 5, is
  `5i-4+k`).

### Reference corpus (independent, pinned)

Per §8 protocol option 2: the **system libharfbuzz 12.3.2** through the
plain C driver `tools/oracle/hb_refshape.c` (no Julia in the loop),
pinned to `test/reference/shaping_reference.tsv` (+ `.sha256` sidecar;
meta records generator, reference version/library, and each font's
sha256/license/source URL). **10 cases** over the pinned fonts
`NotoSansArabic-Regular.ttf` (260740 B, sha256
`7ff958cd…e48830`, OFL 1.1, 1631 glyphs) and
`NotoSansDevanagari-Regular.ttf` (211444 B, sha256
`71f9677a…a2855`, OFL 1.1, 967 glyphs) — fetched pinned by
`scripts/fetch_shaping_fixtures.jl` into `test/fixtures/` — plus
`Roboto-Regular_1.ttf` (upstream-pinned, Apache-2.0) for the ligature
case.

Cases: arab-katab (joining), arab-katab-zinh (script sensitivity),
arab-arabic-digits, ansi-digits-rtl (L2E under an RTL base), latin-fi /
latin-combining (missing glyphs, cluster merge), missing-han (fallback
→ `.notdef`), deva-ksha (single conjunct GID 179/adv 712), deva-akshara
(conjunct absorbs a cluster: gids 9/495/52, clusters 0/1/4),
roboto-fi (ligature: gids f+i → one GID 444, adv 1134).

**The JLL harfbuzz 15.1.0 and the 12.3.2 reference agree on all 10
cases** (gid/cluster/x_advance/x_offset/y_offset identical — probe log
below), so the tests pin the 12.3.2 reference while running on the JLL.

### Supported scripts

- Script detection: vendored UAX#24 `Script` property, BMP subset
  (541 ranges; `src/formats/shaping.jl` header; regenerated by
  `tools/oracle/gen_hb_tables.py` from Unicode 16.0.0 `Scripts.txt`,
  tags matched case-insensitively against harfbuzz 15.1.0's
  `hb-script-list.h`). A run's script = its first non-neutral codepoint
  (Zyyy/Zinh neutral; a neutral-only run inherits the previous run's
  script, §5.4).
- Language defaults (§5.4): Arab→`ar`, Deva→`hi`, Latn→`en`,
  Hani→`zh`, else `en`.
- Shaping correctness is **pinned by the reference corpus for Arabic,
  Devanagari, and Latin (ligature)**; any other BMP script shapes
  through the same provider (no per-script Vetra code) but is not
  reference-pinned — do not claim per-script correctness beyond the
  corpus.

### Bidi (UAX#9, v1 simplification)

Strong L/EN/AN → LTR, R/AL → RTL, else the base direction (neutrals,
WS, controls, astral); the buffer is shaped per run; visual order
reverses strong-RTL segments (and, under an RTL base, the segment
order). L2E: digit runs keep LTR order under an RTL base. Punctuation
mirrors per vendored `Bidi_Mirroring` (428 BMP pairs) before shaping in
RTL-resolved runs. No explicit controls (RLO/LRI/…) — documented limit.
The logical→visual permutation is `ParagraphLayout.shaped`; cluster
indices stay logical. RTL placement follows harfbuzz's own cairo
bridge (`hb_cairo_glyphs_from_buffer`, 12.3.2): a forward pen in buffer
order for both directions (RTL buffers are already visual order).

### Table fix (carried from T028)

The T028 vendored UAX#29 cluster tables (`_CLUSTER_EXTEND`/
`_CLUSTER_MC`) had a range misalignment: base letters (Devanagari
0905/0915/0936, Myanmar 1000..100B, …) were inside **both** tables, so
Indic words clustered as one grapheme. Regenerated from the pinned
Unicode 16.0.0 sources by `tools/oracle/gen_cluster_tables.py` and
round-trip verified codepoint-exact (220 extend / 112 mc BMP ranges;
0 mismatches across the full BMP). One T028 hand-derived expectation
corrected as a result: `"क्ṣ"` (`0915 094d 0937`) is **2** UAX#29
clusters (virama is Extend; a following letter starts a new cluster —
conjunct formation is shaper-level, not grapheme-level), and a new
expectation pins the Mc-vowel-sign join (`0915 094d 093E` → 1).
